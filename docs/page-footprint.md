# What Crittable.js needs, and what it does to your page

A browser from 2023 or later (it uses `:has()`, `color-mix()` and the `translate` property).

It draws itself in a shadow root, so its styles and the page's do not meet. This is everything it does outside that:

- **Elements.** One element at the end of `<body>` for the tool, a second while a note is being written (inside the page's open `<dialog>` if there is one, so it can be typed in), and one `<style>` in `<head>`.
- **That style.** While a note is being placed it sets the cursor and the colour of selected text, through the classes `pw-aim` and `pw-calm` on `<html>`. At all times it tints the words a note quotes, with the CSS highlight `pw-quote`; nothing in the page's markup changes.
- **Padding.** While the panel is open, `<html>` gets inline padding on that side so the page is not covered. When it shuts, whatever inline padding the page had is put back. The tool also sets `--crittable-inset-left` and `--crittable-inset-right` on `<html>` (the panel's width in px on its side, `0px` otherwise) and fires a `resize` on `window` when they change. Padding only moves what is in the page's flow: if your page has fixed-position or `vw`-sized layout, size it from `calc(100vw - var(--crittable-inset-left, 0px) - var(--crittable-inset-right, 0px))`.
- **Keys and clicks.** It listens on the document before the page does: capture listeners for `click`, `pointermove`, `pointerdown` and `keydown`. It takes `C`, `Shift+C`, `J`, `K` and `Escape` only as [Keys](reference.md#keys) describes, never while you type in a field; while a note is being placed it takes the click that places it.
- **Watching the page.** A `MutationObserver` on `<body>` (child nodes and text, the whole subtree), so a pin finds its element again after the page redraws. It also listens on `window` for `resize`, `popstate` and `hashchange`, and with a shared store on the document for `visibilitychange`.
- **Script tags.** The loader adds one `<script>` to `<head>` for each file it loads: `config.js` (unless skipped), `store.js`, `pinwall.js`, and with `data-backend` the adapter and the Persistable.js client (and, with `data-store`, that store's file). All come from the loader's own folder.
- **Scrolling.** Opening a note from the panel scrolls its place into view.
- **History.** It wraps `history.pushState` and `replaceState` for as long as the page is open, so notes follow a single-page app's routes.
- **Globals.** Read: `CRITTABLE_CONFIG` and `CRITTABLE_USER`. Set: `CRITTABLE_CONFIG` by `config.js` when the page has not set it; `CrittableStore`; two flags, `__crittableLoader` and `window['__pin-note-board']` (`'__'` and the `tagName`), so a second copy does nothing. With `data-backend` the loader also sets `CRITTABLE_BACKEND` (the tag's attributes), the adapter sets `CrittablePersistable`, the Persistable.js client sets `Persistable`, and the adapter writes `backend` into `CRITTABLE_CONFIG`, making that object if the page has none. With `data-token-url` the adapter also sets `CRITTABLE_BACKEND_READY` (a promise the loader waits for), asks that address on the page's own site for a token, with the site's cookies, when the page loads and again shortly before each token runs out, and sets `CRITTABLE_USER.name` when the token names the visitor and the page has not.
- **Browser storage.** In `localStorage` (or `sessionStorage` with `storage: 'session'`): `<prefix>.*`, where the prefix is `storagePrefix`, for the notes when there is no shared store, which notes have been read, the reader's settings and, with a shared store, their made-up id and name. In `sessionStorage`: `<prefix>.hint`, which carries the note to open across a move to another page. With `data-store="supabase"`, in `localStorage`: `persistable.supabase.<url>`, the person's session tokens. With Persistable.js, in `localStorage`: `persistable.<url>`, the secret that makes this browser a person, and with `data-key="link"`, `persistable.key.<url>|<space>`, the link's key. Any script on the same origin can read all of these and act as that person, so do not share a store from a page that runs scripts you do not trust.
- **Links between pages.** A note on another page of the same site is a link to that page. On a shared store, anyone who can write notes chooses that address, so a site whose plain links change things (a `/logout` that works by GET) should not share a store with strangers.
